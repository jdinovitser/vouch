VOUCH — COMPLETE HACKATHON BUILD SPECIFICATION
Build the entire application, not a mockup

You are building VOUCH, a polished, technically sophisticated agentic-AI application for the AWS Agents for Humans Hackathon.

This is a serious hackathon submission.

Do not build a generic AI chatbot, productivity assistant, toy, or static dashboard.

Build a complete working prototype that demonstrates a new approach to trustworthy autonomous agents:

AI can act. VOUCH makes it earn the right.

The central idea is:

An AI agent should not receive unlimited authority simply because it can perform an action. It should earn autonomy through demonstrated reliability, evaluate every consequential action against evidence and risk, stop when it cannot establish sufficient confidence, and verify the outcome after acting.

VOUCH is therefore a trust-based agentic action and authorization system.

The core lifecycle is:

REQUEST → INVESTIGATE → EVIDENCE → REASON → RISK → AUTHORITY → ACTION → VERIFY → TRUST UPDATE

The most important thing about this application is that the agent is NOT rewarded for always acting.

The agent is rewarded for making the correct decision about whether it should act.

Sometimes the correct answer is:

ACT

Sometimes:

ASK

Sometimes:

BLOCK

That distinction must be central to the product.

2. THE CENTRAL PRODUCT IDEA

Most agentic systems focus on:

“Can the AI perform the task?”

VOUCH focuses on:

“Has the AI earned enough authority to perform the task?”

Every proposed action passes through a trust decision.

The decision considers:

Evidence quality
Source authority
Evidence agreement/conflict
Action risk
Action reversibility
Agent trust/reliability
Current autonomy level
Whether human authorization is required
Whether the result can be verified

The resulting decision is one of:

EXECUTE

The agent has sufficient evidence and authority.

REQUEST APPROVAL

The agent has a defensible recommendation but the action requires human authorization.

BLOCK

The evidence is insufficient, contradictory, untrusted, unsafe, or otherwise fails the action policy.

The demo must be designed around one unforgettable sequence.

A judge should watch the following happen:

STEP 8

STEP 10

STEP 11

The judge should leave understanding:

“This agent knows when NOT to act.”

That is the primary wow moment.

4. SECOND WOW MOMENT — GRADUATED AUTONOMY

VOUCH must demonstrate that autonomy is not binary.

The agent should have levels.

Implement:

T1 — SUPERVISED

Human approval required for consequential actions.

T2 — ASSISTED

Low-risk routine actions may execute automatically.

Medium/high-risk actions require approval.

T3 — AUTONOMOUS

Routine and selected medium-risk actions may execute automatically when evidence is strong.

T4 — EXPANDED

Broader autonomy is available for proven, low-risk workflows.

Make these levels visually obvious.

The current level should appear in the main dashboard.

Example:

The system should explain:

“VOUCH currently permits autonomous execution for low-risk and verified medium-risk actions.”

The product philosophy:

Promotion is earned. Demotion is immediate.

Implement this concept explicitly.

Do not allow an agent to go from T1 to T4 after two successful actions.

This should feel conservative and trustworthy.
