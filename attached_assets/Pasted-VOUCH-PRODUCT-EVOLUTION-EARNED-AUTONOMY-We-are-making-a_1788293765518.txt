VOUCH — PRODUCT EVOLUTION: EARNED AUTONOMY

We are making a major conceptual refinement to VOUCH.

Do not treat this as a cosmetic redesign.

The goal is to make VOUCH substantially more distinctive and memorable as a hackathon product while preserving the real technical foundation that already exists.

THE NEW CORE IDEA

VOUCH is an earned-autonomy system for AI agents.

The central thesis is:

AI agents don't need unlimited autonomy. They need a way to earn it.

The core product promise is:

VOUCH gives AI agents a verifiable authority that changes based on what they prove they can do.

The fundamental loop is:

ACTION → OUTCOME → EVIDENCE → TRUST → AUTHORITY → ACTION

An agent can:

earn autonomy
exercise autonomy
have autonomy reduced after failure
regain autonomy through demonstrated successful behavior

Human approval is an important safety mechanism, but it is not the primary product concept.

The primary concept is:

Dynamic authority based on demonstrated performance.

PRODUCT DIFFERENTIATION

VOUCH should NOT feel like a generic:

AI safety dashboard
approval workflow
risk dashboard
human-in-the-loop product
AI copilot with guardrails
static permissions system

Those mechanisms can exist underneath the product, but the visible product story must be:

EARNED AUTONOMY

The judge should understand that VOUCH is different because an agent's history affects what it is permitted to do next.

The important conceptual distinction is:

Static permissions

This agent is configured to perform X.

VOUCH

This agent has demonstrated that it can perform X reliably enough to earn that authority.

And importantly:

Authority can be lost.

And:

Authority can be earned back.

Before changing anything, inspect the existing codebase and understand the current implementation.

Do not throw this away.

Do not replace the deterministic authority layer with an LLM.

The architectural boundary should remain:

The agent MUST NOT be able to grant itself authority.

VOUCH's authority decision must remain independently enforced server-side.

AUTONOMY MODEL

Create a clear conceptual model around four autonomy levels.

T1 — OBSERVE

The agent can observe and analyze.

It cannot act autonomously.

T2 — RECOMMEND

The agent can recommend actions.

A human or higher authority must authorize consequential actions.

T3 — ACT

The agent can autonomously perform actions within its earned authority.

T4 — DELEGATE

The agent has demonstrated enough reliability to operate with broader delegated authority.

The exact implementation can use existing autonomy terminology if it already has a coherent equivalent, but preserve the fundamental progression:

Observe → Recommend → Act → Delegate

The critical concept is:

Authority is earned, not permanently assigned.
THE MOST IMPORTANT PRODUCT MECHANIC

Trust must NOT merely be a number displayed on a dashboard.

Trust must have consequences.

For example:

An agent begins:

T2 — RECOMMEND

It demonstrates successful verified behavior.

Its authority increases:

T2 → T3

Then a consequential action fails verification.

VOUCH visibly changes the agent's authority:

T3 → T2

Display:

AUTONOMY REDUCED

Then explain:

Verification failed. This agent is no longer trusted to perform this action autonomously.

The agent is not permanently punished.

Successful verified behavior can eventually restore authority.

This creates the core lifecycle:

EARN → ACT → VERIFY → LOSE → RECOVER

That lifecycle should become the heart of the product.
